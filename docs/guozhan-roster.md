## 4. 阶段 1 的工程底座（已做 + 调整说明）

### 4.1 体力与阴阳鱼的换算（已查清，引擎无需改）

一度以为「国战体力与身份局不同」——核对下来是**我的误解**，引擎的算法本来就是对的。
正确的换算是：

> **国战武将牌上印的阴阳鱼数 = 身份局体力 ÷ 2。**
> 双将的体力上限 = 两将阴阳鱼之和（半格配对成 1，配不上的半个转成阴阳鱼标记）。

它和引擎用的 `floor((主将体力 + 副将体力) / 2)`（吃**身份局**体力）是等价的，
因为那个 `/2` 做的正是「阴阳鱼数 → 体力」这一步。对账：

| 组合 | 牌面阴阳鱼 | 官方上限 | 引擎 `floor((a+b)/2)` |
|---|---|---|---|
| 关羽 4 + 张飞 4 | 2 + 2 = 4 | 4 | `floor(4)` = 4 ✓ |
| 董昭 3 + 许褚 4 | 1.5 + 2 = 3.5 | 3（余半） | `floor(3.5)` = 3 ✓ |
| 卧龙 3 + 孟获 4 | 1.5 + 2 = 3.5 | 3（余半） | `floor(3.5)` = 3 ✓ |

**所以填 `maxHp` 时要填身份局口径的值**（董昭填 3，不是 1.5——我第一版填错成 1.5 已修正）。
`阴阳鱼` 的奇偶判断写 `% 2 !== 0`（不是 `=== 1`），这样半格值也能正确判定出「余半个」。

（顺带：2025 公告把夏侯惇的国战体力改成 2.5 阴阳鱼 = 5 体力，属于平衡性调整；
引擎仍按身份局的 4 填，数值上恰好等价，待有权威表再统一核对。）


**已做**：`Hero.modes` 字段 + `poolForMode(mode)`。国战专属武将（甘夫人、丁奉、马腾、孔融、纪灵、田丰、潘凤、邹氏）

### 5.1「钩子内发起询问」的实现与用法（阶段 2.1，已完成）

**问题**：伤害/结算路径在 `runHooks(...)` 之后会无条件改 `state.pending`
（例如 `finishAttack` 里 `runHooks('afterDamage')` 紧跟着 `resumePlay()`）。钩子若在中间发起询问，
pending 会被这行直接覆盖，玩家看不到询问——表面上像技能没生效。

**解法**（`engine.ts`）：

1. `GameState.resumeQueue`：被询问打断的后续流程压进这个队列。
2. `runHooksPausable(state, timing, player, payload, onDone)`：与 `runHooks` 的区别是允许钩子挂起。
   某个钩子挂起后**后面的钩子先不跑**（否则会覆盖 pending），把「剩下的钩子 + `onDone`」压进队列。
3. `applyIntent` 末尾统一调 `drainResume()`，且**只在 pending 为空时**执行队列。
   这样级联也正确：如果这次询问的结果又引发濒死等新流程，队列会一直等到那串流程走完才继续。
   有 100 次上限兜底，防止续接互相触发形成死循环挂死进程。
4. `HookContext.api`：钩子通过它拿 `askChoice` / `dealDamage` / `loseHp`。
   钩子里发起询问**不要传 `returnTo`**——续接队列负责接回来，传了反而会和它抢 pending。

**已转换（可挂起）的时机**：`afterDamage`、`afterDamageDealt`、`becomeTarget`、
`turnStart`、`judgePhase`、`drawPhase`、`playPhase`、`turnEnd`。
**尚未转换**：只剩 `beforeResolve` / `afterResolve`（这两个是纯引擎内部的伤害时机，
**没有任何技能挂在上面**，所以不影响任何技能行为）；`afterUse` 目前只在【调虎离山】那条路派发。
`nearDeath` / `discardPhase` / `death` 其实早就是可挂起的（文档这里写旧了，已更正）。

**想用「钩子内询问」的新技能必须挂在已转换的时机上**，否则询问会被静默吞掉。
新增时机时同步更新 `roster.ts` 的 `PRIMITIVES_DONE` 注释与本节。

**验证**：夏侯惇·刚烈（来源二选一）端到端跑通，含最难的**级联用例**——刚烈打出致命伤害、
询问结束后先进濒死、濒死走完续接才继续，控制权最终回到正确玩家。回归测试见
`tests/engine.test.ts` 的「夏侯惇·刚烈」四条。

**顺带修掉的两个保真度问题**：洛神与闭月官方都是「**可以**」，原来实现成无条件自动发动，
玩家没有选择权；现在会先问一句。

### 5.2 选牌原语（阶段 2.2，已完成）

**解决的问题**：很多技能要「从一组牌里挑若干张」，而这组牌**不一定在选牌人的手牌里**——
观星看的是牌堆顶。所以 `pickCards` 与 `discard`（弃自己手牌）是两套东西。

**接口**：

- 引擎：`askPickCards(state, seatId, title, cards, min, max, resolve, opts?)`
  - `cards` 是引擎侧真实牌对象；**本函数不动任何牌**，`resolve` 里要自己搬走
  - `resolve` 收到被选中的牌对象（不是 id），省得再查
  - `opts.secret`：私密选牌（观星）。日志只记张数不记牌名，否则等于把牌堆顶公开了
  - `opts.returnTo`：技能 `execute` 里发起的必须传；钩子里发起的**不要传**（走 2.1 的续接队列）
- 协议：`PromptKind` 加 `pickCards`；`PromptView.pickCards` 下**完整牌面**（不是 id，
  因为界面拿 id 去 `myHand` 查不到牌堆顶的牌）；`Intent{type:'pickCards', cardIds}`。
- 界面：`Game.tsx` 里 .pick-cards 浮层单独铺一行牌面（不复用手牌区），选完点确定。
  候选牌变化也会进 `promptKey`，避免换了问题还留着旧选择。

**验证**：两个真实用户——夏侯惇·刚烈（选自己手牌弃两张）、诸葛亮·观星（选牌堆顶的牌沉底），
含私密日志与牌堆顺序两个易错点。回归测试见「选牌原语与观星（阶段 2.2）」。

**观星的简化**：官方是「以**任意顺序**置于牌堆顶或牌堆底」，本实现只让玩家选「哪些沉底」，
留在牌堆顶的保持原序。顺序自由需要带排序的选牌界面。

**顺带修的一处真缺陷**：钩子发起的询问会**覆盖**掉当时的环境 pending
（出牌阶段是 `{kind:'play'}`）。装装备触发枭姬这条路径原本不重设 pending，
选完就成了 `null`、玩家卡死。修法不是逐处打补丁，而是在 `runHooksPausable` 里
记下被覆盖的 pending，等整条钩子链跑完、且调用方没有产生新 pending 时还回去
（`gameOver` 时不还）。这是防住「钩子暂停吃掉 pending」这一类 bug 的通用兜底。

**验证技能**：枭姬（装备顶替/被拆两条路径）、天妒（收自己的判定牌 + 不抢别人的）、
裸衣（国战版与身份局版两种时机与代价）、遗计（三段续接：是否发动 → 挑牌 → 选目标）。

### 5.4 卡牌效果与技能补完（本轮）

**标准版·魏收尾（第三批）**：夏侯渊·神速、乐进·骁果、徐晃·断粮。三个各带一点引擎扩展：

- **虚拟杀**：`api.castVirtualSha`（与虚拟锦囊 `castVirtualTrick` 对应）。它复用
  `resolvePlayedSha`，所以走的是和实体【杀】一模一样的结算（防具、八卦阵、流离、等出闪），
  只是没有实体牌。夏侯渊·神速靠它。
- **`othersTurnEnd` 时机**：`turnEnd` 只派发给回合玩家，而「**其他角色**的结束阶段」
  要派发给其余的人。新增该时机 + `runOthersTurnEnd()` 依次派发（每人都可能发起询问）。
  乐进·骁果靠它。
- **`skipJudgment` 标记**：神速的「跳过判定阶段」是**整个阶段不处理**，
  所以判定区的延时锦囊会原样留着、下回合再判——测试专门断言了这一点。
- **转化分支泛化**：`legal.ts` 原来只处理大乔·国色的 `lebu`，现在 `lebu`/`bingliang`
  一起走同一个循环。徐晃·断粮靠它。

**⚠️ 徐晃有一处界面限制（已在名录里标注）**：断粮是「黑色基本牌或黑色装备牌当【兵粮寸断】」，
但黑色【杀】【装备】本来就能直接使用，而界面的用法选择**只对「不能直接使用」的牌给转化**
（`cardAsType` 开头就 `if (isDirectlyPlayable(card)) return undefined`）。
所以目前只有黑色【闪】【桃】会走断粮。这个问题 `甘宁·奇袭`、`大乔·国色` 也一直存在，
要完整支持得给界面加「选择用法」——值得单独一轮。


**曹丕**（标准版魏第三批）：行殇 + 放逐。

**行殇带出一个新时机**：引擎只有 `death`（派发给**死者**），而「当你杀死一名角色后」
必须派发给**凶手**——所以加了 `kill` 时机。另外它有个顺序要求：
行殇要在**死者的牌被清进弃牌堆之前**拿到它们，所以 `doDeath` 拆成了两段
（先跑 `kill` 钩子 → 再清牌）。`killerId` 要从 `enterNearDeath` 的 attack 一路传到
`respondDeath` 上，否则等濒死询问走完就不知道凶手是谁了。

**放逐**直接用 `flip`，没有新机制。

**标准版·魏补完（第二批）**：曹仁·据守、典韦·强袭、荀彧·驱虎/节命。

**这批带出一个真 bug，值得单独记**：做曹仁·据守时发现，**翻面跳过回合的那条路仍在跑
结束阶段钩子**（`startTurn` 里走的是 `endTurn`），于是据守会在被跳过的回合里**再触发一次**——
又摸三张又翻面，翻面来回循环。修法：跳过的回合直接 `afterTurnEnd`，
**不跑任何阶段钩子**（跳过的回合本来就没有阶段）。测试里专门断言了
「翻回来后 `flipped` 为 false、回合交给了下家、没再摸牌」。

另外两条失败是**测试自己的问题**，也一并说明了当时的设计：
- 劝进测试写死了「董昭摸一张」，但军令是**随机抽**的——抽到「摸一张再收两张」那条会更多。
  改成只断言下界，并在注释里说明为什么不能写死。
- 驱虎「拼点没赢」那条：荀彧自己受伤会触发**他自己的节命**，测试得先把这个询问问掉。


**军令（`army_order`）**：国战·不臣篇特有，董昭是第一个用户。**规则是先查清再动手的**。

军令不做成实体牌——它只是一个「发起者从六条里随机抽两条、挑一条交给执行者；
执行者选执行或不执行」的挑选项，所以放成数据表 `ARMY_ORDERS` 最省事。
六条效果里**有两项正好复用前面做好的原语**：「所有非锁定技失效」用 `skill_nullify`、
「翻面」用 `flip`。

董昭是 **1.5 阴阳鱼**体力——引擎一直把 `maxHp` 当整数。查下来只需一处小修正：
体力上限公式 `floor((a+b)/2)` 天然支持半格（`floor(5.5/2)=2`），
但阴阳鱼的「有没有余半个」判断**不能写 `% 2 === 1`**（`5.5 % 2` 得 1.5，不是 1），要写 `% 2 !== 0`。
他也是第一个 `modes: ['guozhan']` 的国战专属武将，顺带验证了那个字段真在过滤选将池
（一条老测试因此失败并已修正）。

**踩到的坑**：「本回合受到过伤害的角色」（劝进的目标条件）我一开始只挂在 `runHooks` 里，
但伤害路径大多走 **`runHooksPausable`/`runHooksFrom`**，绕过了 `runHooks`，结果标记永远是空的。
两个入口都要调。另外劝进是技能发起的多步链，走完 `pending` 会停在 `null`——
和 `pindian` 同一个坑，修法也一样：给 `armyOrder` 加统一的收口 `finish()`
（先让技能结算收益，再在 `pending === null` 时 `resumePlay(resumeTo)`）。

**觉醒技（`awaken_skill`）与「获得技能」**：前置是「**动态获得技能**」——
姜维·志继要获得诸葛亮的【观星】、孙策·魂姿要获得【英姿】【英魂】，
所以得能把技能从**别的武将**身上摘过来。为此补了三样：

- `HookRegistration.skillId`——钩子没有拼音 id，所以填**技能中文名**
  （与 `skills[].name` / `ActiveSkill.name` 同一套），按它摘钩子。
- `Hero.skillFields`——技能名 → 它「拥有」哪些字段型能力。
  周瑜的【英姿】其实是由 `extraDraw` 实现的，不记这个就摘出个空壳。
- `Player.grantedSkills` + `heroes.grantedHeroes()`：把指定技能打包成一个**合成武将**
  （只留那一条钩子/一个主动技/那几个字段），塞进 `effectiveHeroes`。
  这样 `runHooks` / `activeSkills` / 各字段的消费方全都能原样工作，不用改。

`api.grantSkill(heroId, skillName)` 供技能调用；`makeSkillApi` 因此多了一个 `actor`
（这次是**谁**在行动）——钩子路径从 `player` 取，技能路径由 `resumeTo` 兼职。

**注意**：觉醒技按定义是**锁定技**，满足条件**必须**发动，所以志继不问、直接结算
（和洛神/闭月那种「可以」不同）。

**验证**（4 条测试）：无手牌时觉醒（上限 4→3、当前体力跟着夹下来）、有手牌不觉醒、
获得的【观星】**从下一回合**开始生效（这一回合的钩子列表已经取好了，所以不会当场生效）、
以及「非锁定技失效」挡不住觉醒技。

**非锁定技失效（`skill_nullify`）**：这个原语有一个**之前没预料到的前置**——
「非锁定技失效」必须知道哪些技能是锁定技，而代码里**根本没有这个字段**
（6 处「锁定技」此前全都只写在 `desc` 字符串里）。所以先补了标记体系：

- `HookRegistration.locked`（钩子型：咆哮/狂骨/无双）
- `ActiveSkill.locked`（主动技；目前没有锁定类的主动技）
- `Hero.lockedFields`（**字段型**技能：马术/奇才/空城/谦逊/帷幕/完杀/救援/英姿）。
  名字与 Hero 上的字段同名，便于对照；`ALL_FIELD_SKILLS` 列出全部候选。
  **没列进 `lockedFields` 的字段会被摘掉**——所以武圣/龙胆这类转化技会被屏蔽，
  马术/空城不会，这正是要靠标记区分开的。
- `effectiveHeroes(state, p)` 统一做屏蔽（`PlayerFlags.nonLockedSkillsDisabled`），
  **引擎的 `activeHeroes` 与 `distance.ts` 的马术都走它**，所以两处口径一致——
  否则会出现「武圣被屏蔽了但马术还生效」这种不一致。
- `afterTurnEnd` 统一清掉该标记（语义是「直到回合结束」）。
- `api.nullifyNonLockedSkills(目标)` 供技能调用。

**验证**（6 条测试）：武圣被屏蔽 / 马术·空城·狂骨（锁定技）不受影响 /
遗计这类非锁定钩子被屏蔽 / 回合结束自动清除。

**注意**：机制完整且有测试，但**还没有武将在用**——新国战·铁骑与左慈·化身的技能文本
都还没核对（左慈要的其实是「化身」那套借技能机制，与 `awaken_skill` 的需求重叠）。

**虚拟锦囊（`virtual_trick`）**：把 `playTrick` 里「牌已经打出去了」之后的部分抽成了
`startTrickResolution(state, 玩家, 牌, targetIds, targetCardId)`（构建上下文 → 无懈询问 → 结算），
技能的 `api.castVirtualTrick(来源, { type, suit, rank }, targetIds?)` 直接复用它。

- 虚拟牌没有实体，id 用 `virtual-<logSeq>-<type>` 保证唯一；它不会进任何牌堆。
- **要传花色**：帷幕那类「不能被黑色锦囊指定」的锁定技靠它判断。乱击沿用弃掉那两张的花色，
  测试里专门验了「黑桃万箭会被帷幕挡掉」。
- 第一个用户是袁绍·乱击（两张同花色手牌当【万箭齐发】）。
- **顺带纠正**：袁绍在国战里**不是君主**，所以【血裔】是主公技、不该收录；
  之前名录把他当君主候选，现在只留【乱击】。
- 还没做：荀攸·奇策（把「所有手牌」当**任意**即时锦囊，需要先让玩家选锦囊类型）。
- 也还没做：丈八蛇矛——它要的是**出牌路径**接受多张牌，与乱击走 activeSkill 不是同一条路，
  等 `playCard` 的牌数放宽之后再一起做。（方天画戟不在国战标准堆里，见 §5.14。）

**拼点（`pindian`）**：**不需要新的 pending 类型**——复用选牌原语就够。
`api.pindian(发起者, 目标, onResult)` 依次问两边各扣一张手牌，**扣牌阶段用 `secret` 不公布牌名**，
两边都扣好才一起亮、比点数、两张进弃牌堆。第一个用户是太史慈·天义（拼点赢了本回合
额外一张【杀】且【杀】无距离限制，为此加了 `flags.ignoreShaDistanceThisTurn`）。

**横置（`chained`）**：`Player.chained` + `api.chainPlayers`，核心是**属性伤害的蔓延**。

- 蔓延的驱动方式值得记一笔：**不能用「pending 非空」判断是否被打断**——结算过程中
  pending 一直是**旧值**（`onPass` 之类不会清理它），所以我第一版误把正常结算当成挂起、
  直接死循环。正确做法是照 AOE 那套：先 `queueChainSpread` **只记账**（重置横置目标、
  把要蔓延的座次记进 `state.ongoingChain`），真正开跑由 `runChainSpread` 负责；
  中途有人被打进濒死就让濒死流程接管，**剩下的等 `resumePlay` 接着跑**。
- 这带来一条能被测试抓到的关键行为：蔓延途中第一个人濒死、后面的人**照样要受伤害**。
- **【铁索连环】已进牌堆**（见 §5.7），庞统·连环 用 `canUseAs(梅花手牌→tiesuo)`
  实现，含「或重铸」。

**势力技（`faction_call`，已完成）**：结构与 `wuxieQueue` 相同——一个按座次询问的队列。

- 新增 `Pending{kind:'factionCall'}` + `Intent{type:'factionCall'}` + `PromptKind`；
  响应侧复用 `respondCard`/`pass`。
- 场景用 `FactionScene` 联合类型表达，**一次写了六种**：需要【闪】的被杀指定、万箭齐发；
  需要【杀】的决斗、南蛮、借刀、离间（离间是技能造的虚拟锦囊，走 `ctx.skillId === 'lilian'`）。
  `legal.ts` 的 `respondNeedType` 与 `engine.ts` 的 `factionCallScene` 一一对应——改一边要改另一边。
- 持有者（曹操·护驾 / 刘备·激将）在对应提示里会多出 `PromptView.factionCall`，界面据此给按钮。
- 代打成功 → `onCard` 把那张牌算作**发起者**打出的，接回该场景原本的收尾；没人代打 → `onNone` 还原提示。

**顺带修掉的一处漏判**：借刀杀人与离间的强制出杀，以前只跑了 `becomeTarget` + 「不可闪避」，
**漏了防具与八卦阵**（仁王盾/藤甲/八卦阵对这两条路的杀无效）。现在统一走
`resolvePlayedSha → becomeTargetFor → afterShaBecomeTarget`，顺带让大乔·流离也能对这类杀生效。

**孙权·救援**不是势力技询问，是纯加血规则：同势力的**其他**角色用【桃】救你时额外回 1 点，
在 `respondDeathSave` 里按 faction 判断即可（`Hero.rescueHealBonusFromFaction`）。

**武器特效**（引擎里 `EQUIP_NOT_IMPLEMENTED` 原本列了 6 件）：

| 武器 | 实现要点 |
|---|---|
| 贯石斧 | 【杀】被【闪】抵消后，问是否弃置两张牌 → 弃完仍造成伤害。候选含手牌与装备区（排除武器本身），逐张弃置以免漏掉「失去装备」的钩子 |
| 青龙偃月刀 | 被抵消后问是否继续出一张【杀】→ 挑牌 → 复用 `startAttack` 重开一次杀结算。**追加的【杀】不计入本回合出杀次数**（`countTowardLimit: false`） |
| 雌雄双股剑 | 指定**异性**目标后，由**目标**选择：弃一张手牌 / 让使用者摸一张。目标没手牌时不摆「弃牌」选项 |

为此把 `playSha` 拆出了 `startAttack`（目标已校验、开始结算），并把 `finishAttack` 拆成
「被闪避」与 `resolveAttackHit`（命中结算）两段。

**仍未实现的 3 件**（都在 `EQUIP_NOT_IMPLEMENTED` 里，提示会如实标注）：
丈八蛇矛（两张手牌当【杀】）需要「多牌转化」，朱雀羽扇（普通【杀】当火【杀】）需要协议层带上
「转化后的属性」。**方天画戟不是国战标准堆的牌**（它和古锭刀/青龙偃月刀一起被国战踢掉了，
势备篇里是另一张同名不同效果的牌，见 §5.14），列在这里只是因为 `EQUIP_NOT_IMPLEMENTED`
是全局一张表、不分模式。

**技能补完**：司马懿的反馈与鬼才从「简化版」改成完整版——
反馈改为**由自己挑**一张来源的牌（走 `api.transferCard`，拿装备会触发枭姬那类）；
鬼才改为**手动选牌替判**。

为此给判定链加了一个通道：`HookResult.replaceCard` 是同步返还的，而「换哪张」要问了才知道，
所以加了 `JudgeBox` + `api.replaceJudgeCard`——钩子先询问，在回调里声明结果，
`judgeHookStep` 会把被挂起的判定流程接回来再继续下一个钩子。

**`api.transferCard`**（顺带加的通用能力）：把某人的一张牌转给别人，拿走装备会触发失去装备的技能。
反馈、突袭、顺手牵羊那类「获得他人一张牌」都该走它，不要自己 splice。

**新武将**：张辽（突袭）、刘备（仁德，激将未做）。

- **突袭**：挂在 `drawPhase`（摸牌**之前**），所以它设的 `drawCountDelta` 会被紧接着的摸牌读到。
  流程是「问是否发动 → 少摸一张 → 至多选两名角色 → 逐张挑他们手里的一张」——
  选人阶段给了「不再选人」选项，因为官方是「至多两名」。拿哪一张由张辽选（会看到对方手牌）。
- **仁德**：不限次数（可以分几次给），用 `flags.skillNumbers.rende_given` 累计本阶段给出的张数，
  **首次达到两张**时回 1 点血（用 `skillUsedThisTurn.rende_healed` 保证只回一次）。
  为此给 `PlayerFlags` 加了通用的 `skillNumbers`（技能自己的每回合计数，随 `emptyFlags` 清零）。

涅槃（濒死时发动，被救回后不进求桃队列）、翻面（跳过回合并翻回正面）。

### 5.6 回合内「进入弃牌堆的牌」账本与三个新时机（已完成）

这一轮为了甘夫人/孟获补了引擎里三处缺口，都是可复用的：

| 机制 | 位置 | 说明 |
|---|---|---|
| `afterHeal` 时机 | `timing.ts` + `healAndTrigger`（engine.ts） | 「回复体力后」派发给**回复者**，`payload.amount` 是**实回量**（被体力上限夹过）。满体力时不触发 |
| `toDiscard()` | `model.ts` | 进弃牌堆的**唯一入口**，同时记进 `state.discardThisTurn`。53 处 `state.discard.push` 已全部迁移 |
| `discardPhaseEnd` 时机 | `timing.ts` + `runDiscardPhaseEnd` | 弃牌阶段**结束时**（弃完牌之后）。孟获·再起挂这里 |

**为什么要 `toDiscard` 而不是「回合开始时记下弃牌堆长度，结束时切一段」**：牌堆抽空时
`drawOne` 会把整个弃牌堆洗回牌堆（`state.discard = []`），长度会倒退，切片就不成立了。
账本不受洗牌影响——那些牌确实「进入过弃牌堆」，规则上仍然要算。

**回复体力的所有路径都改走 `healAndTrigger` / `api.heal`**：桃、桃园结义、濒死救援
（这一处不走 `healAndTrigger`，因为濒死时体力 ≤0，回复量不该被上限夹取）、青囊、结姻、
仁德、狂骨、涅槃（`3 - 当前体力`）。哪一条漏了，淑慎就会漏触发。

**`skillNameForField()`**：日志里要说出正确的技能名。此前「南蛮入侵对你无效」这条日志
**硬编码成【巨象】**，孟获的【祸首】会被写成祝融的技能——现在读 `Hero.skillFields`
反查技能名（顺带让 `skillFields` 多了第二个用途：摘技能之外的日志归因）。

**孟获·再起的口径**（用户指定）：X = **本回合进入弃牌堆的红桃牌数**。注意官方不同版本文本
在「红色牌 / 红桃牌」与「是否限同势力」上互相冲突，本实现取红桃那一版、目标不限势力，
`RosterEntry.note` 里记了这一点。


### 5.7 欠账一：牌堆分模式与国战专属锦囊（已完成）

**问题**：国战此前跑的是**军争牌堆**。军争堆里没有【铁索连环】【知己知彼】【以逸待劳】
【远交近攻】，也没有国战独有的武器坐骑，所以整个牌层是「像国战」而不是国战。

**做法**：`buildDeck(mode)` 分派到 `buildGuozhanDeck()` / `buildJunzhengDeck()`，
`createGame` 传 `mode` 进去。国战堆 id 前缀 `g`、军争堆前缀 `c`，测试据此断言用的是哪一堆。

**三条需要说明的取舍**

1. **重铸**是一等公民：`Intent{type:'recast'}` + `RECASTABLE_CARD_TYPES`。
   它**不是「使用」**——重铸【铁索连环】不触发 `useCard` 钩子（黄月英重铸不发动【集智】）。
   庞统·连环 的「或重铸」因此不用另写代码：`canRecastCard` 认的是
   「这张牌本身可重铸，或有转化技把它变成可重铸的牌型」。
2. **铁索连环不做逐目标询问**。官方是「分别横置或重置」，但另一个选项在任何情况下
   都是空操作（对未横置的角色选重置、对已横置的选横置都不改变状态），所以直接取反。
3. **私密信息有了通道**：`Pending{kind:'viewCards'}` 只下发给 `seatId` 那一张快照，
   别人的 `prompt` 是 `null`，日志里也不出现看到的内容。这是**后续所有「观看」类技能的地基**。

**牌面数据的诚实声明**：两个堆的**花色点数是近似值**——只保证每种牌各几张与官方一致，
个别位置会与别的牌重复（引擎不依赖花色点数的唯一性）。测试断言的是张数与种类。

### 5.10 国战「预亮」与技能声明（已完成）

**问题**：`activeHeroes` 只返回**已明置**的武将，所以暗置时触发技的钩子根本不跑
（时机到了不询问），主动技也点不动——暗置武将等于什么都没有。

**规则**（查证自官方国战基础规则与线上实现）：
- 暗置的武将牌**没有任何技能、性别与势力**；
- 明置时机：①准备阶段开始时 ②**发动技能时**（发动技能必须明置该武将）；
- **预亮**：暗置时先把某个技能标成「想发动」，它的时机到来时系统才询问；选「发动」则
  明置武将牌并执行。**没预亮就不问**——这正是「读条识武将」的信息博弈来源。

**实现**

| 环节 | 做法 |
|---|---|
| 状态 | `Player.prelitSkills: string[]`（技能中文名）。不随回合清空，**不公开给对手** |
| 意图 | `{type:'prelightSkill', skillName}`，再发一次即取消 |
| 钩子分发 | `collectTimingHooks()` = 已明置武将的钩子 + 暗置武将里**已预亮**技能的钩子；没预亮的不进列表，所以不会产生任何询问 |
| 询问 | 可挂起的时机：先问「是否明置【X】并发动？」，确认后 `revealHeroCard()` 再跑原钩子 |
| 同步时机 | 本来 `beforeResolve / afterResolve / death` 这类挂不起询问 → **预亮即视为决定发动**（`autoRevealHook`）。**现在这条降级路径实际上走不到了**：能挂起的时机已经全部转换（`useCard` 于 §5.34 收尾），剩下两个同步时机（`beforeResolve`/`afterResolve`）没有任何技能挂靠，所以预亮一律走「先问是否明置并发动」那条路 |
| 主动技 | 暗置武将的主动技也进 `legalSkillIds`；点击 = 明置 + 发动（点击本身就是玩家的决定） |
| 转化技 | 暗置 + 预亮过 → `canUseAsCard` 返回 true，真正打出去时 `revealForConversion` 明置 |
| 界面 | 技能按钮三态：`.dark`（虚线，可点=预亮）、`.prelit`（实线金边）、正常。可预亮名单随**本人快照**下发（不是出牌提示），所以**别人的回合里也能预亮** |

**顺带补的两处**：
1. **21 个钩子补上了 `skillId`**（天妒/遗计/反馈/鬼才/刚烈/裸衣/洛神/闭月/奸雄/突袭/据守/
   放权/流离/连营/枭姬/铁骑/烈弓/狂骨/集智/无双/涅槃）。没有它，「预亮哪个技能」就无从表达——
   `prelitableSkills` 与询问文案都要按技能名说话。
2. **9 个转化技武将补了 `skillFields`**（武圣/龙胆/火计/看破/连环/倾国/断粮/急救/奇袭/国色），
   这样「这个转化技是哪个技能给的」有据可查（同时也让「获得技能」能带走字段）。

**仍然没动的**：`passiveReveal`——成为【杀】目标 / 濒死时**自动亮双将**的旧简化还在。
它和预亮是冲突的：暗置玩家一出闪就被自动亮将，预亮【倾国】【龙胆】就没意义了。
没动它是因为它带着两个既有测试、且不在这次的要求里，但它应该是下一个要改的地方
（改成「需要转化技时询问」）。

### 5.11 明置时机：只有「准备阶段开始时」+「发动技能时」（已修正）

**我一开始做错了**：把主动亮将放宽到「自己的整个回合」，界面上出牌阶段也一直挂着「亮将」按钮。
按官方规则这是错的：

> 暗置武将牌明置的时机：①**准备阶段开始时**（可主动明置主将/副将/全部）②**发动技能时**
> （发动技能必须明置该武将）。**出牌阶段本身不是明置时机**——那时只能靠发动技能顺带明置。

**为什么这个错误代价不小**：常驻字段技（马超·马术、张飞·咆哮、小乔·红颜…）暗置时不生效，
也**没有「询问是否发动」这一步**，它们唯一的出场方式就是准备阶段亮将。而引擎此前**根本没有
准备阶段这个交互入口**（判定/摸牌阶段是自动跑过去的，玩家没有点击窗口），所以那些武将等于
永远没法靠亮将生效。

**修正后的实现**：
- `startTurn` 最前面问一句「准备阶段：是否明置武将牌？」，选项按当前能亮的牌拼：
  明置主将【X】/ 明置副将【Y】/ 全部明置 / 暂不明置；君主将合并成「全部」。
  没有暗置武将时不问（已亮完的玩家不会被反复打扰）。
- `revealHero` 意图收紧到**准备阶段**（引擎里准备阶段与判定阶段同属 `'judgment'`），
  出牌阶段发这个意图会被拒——那时要明置只能通过发动技能。
- 界面「亮将」按钮同样只在准备阶段露出。
- ⚠️ 这个询问**不能传 `returnTo`**：那走的是 `resumePlay`（直接跳到出牌阶段），会把
  判定/摸牌阶段整个跳掉。续接由 resolve 自己调 `after()` 完成。

### 5.12 暗置语义补完：删掉 passiveReveal，补上「没有性别/势力」（已完成）

**删掉 `passiveReveal`**（4 个调用点：成为杀目标前 ×2、流离改目标后、濒死时）。它是早期的
自动亮将简化，和预亮机制直接冲突——暗置玩家一出闪就被自动亮将，预亮【倾国】【龙胆】就白费了。
删掉之后这些技能各自走正确的通路：转化技靠**预亮 + 用出去时明置**（`revealForConversion`），
触发技靠**预亮 + 时机询问**。行为差别（都有测试）：

| 场景 | 删掉之前 | 现在 |
|---|---|---|
| 暗置被【杀】指定 | 自动亮双将 | **不亮**；没预亮倾国/龙胆就用不了（暗置武将没有技能） |
| 暗置预亮了倾国 | （来不及用，已经亮了） | 黑牌出现在可出列表，打出去才明置 |
| 暗置濒死 | 自动亮双将 | **不亮**；预亮了【涅槃】才会问「是否明置并发动」 |

**补上「暗置的武将牌没有性别与势力」**（这条规则我只做了一半）：

- 性别：`isMalePlayer` 以前直接读 `player.heroId`，**暗置照样算男性**——雌雄双股剑、结姻、
  离间都会误判。现在取**明置**的武将牌，且两张都明置时按官方规则**取主将的性别**。
- 势力：新增 `effectiveFaction()` —— 暗置返回 null（暗将之间互视为不同势力）。
  用在**互相认同**的判断上：护驾/激将（factionHelpers）、救援、以逸待劳、远交近攻。
- ⚠️ **两类不要用它**：①胜负判定 / 野心家判定——势力选将时就定下了，暗置只是别人不知道；
  ②鏖战那种**客观残局条件**（`isAoyu` 数场上还剩几个势力，暗置角色照样数进去）。
  我一度把 `isAoyu` 也改成 effectiveFaction，测试立刻抓住了这个错误，注释里写清了原因。

### 5.20 丈八蛇矛（两张手牌当【杀】）—— 国战装备特效收尾

这是国战标准堆里**最后一件**没做特效的装备，卡在「出牌路径只接受一张牌」上。
做完之后，国战标准堆 + 势备篇的装备特效**全部实现**。

**官方口径（查证过，和「一律无色」的想当然不同）**：

> 你可以将两张手牌当【杀】使用或打出。

颜色按两张牌算，口诀是「**两红为红，两黑为黑，黑红无色**」；而【仁王盾】只挡**黑色**杀，
所以**一红一黑凑出来的无色杀反而能破仁王盾**。虚拟杀**无属性**（藤甲的「普通杀无效」照常生效）。

**实现**：

| 层 | 改动 |
|---|---|
| 协议 | `Card.materials`（虚拟牌由哪些实体牌凑的）、`Card.virtual`/`Card.color`；`cardColor(card)`（**唯一**的颜色入口，可能返回 null＝无色）与 `zhangbaShaColor(cards)`；意图加 `extraCardIds` |
| 攻击管线 | `AttackContext.cardRed` → **三态** `cardColor: 'red' \| 'black' \| null`（仁王盾判 `=== 'black'`）。原来那个 `!cardRed` 的写法把无色当成黑色，这次不改成三态就会踩 |
| 计价 | `consumeCard(state, player, card)`：虚拟牌收的是 `materials` 里的两张手牌，**两张同时**进弃牌堆；普通牌照旧收自己。所有「使用/打出」的移除点都改走它 |
| 解析 | `resolveUsedCard`：带 `extraCardIds` 就是丈八——校验装备、校验**正好两张**、不许同 id，然后造虚拟【杀】。`onPlayCard` 与各响应路径（南蛮/决斗/借刀/离间/势力技代打）都过它 |
| 合法性与提示 | `legal.canZhangba` + `respondCandidates`：装备着丈八时，**整手牌都可点**（任意两张都能凑成杀），提示里加一句怎么用；`PromptView.zhangbaOk` 由服务端下发 |
| 界面 | 一条「丈八模式」：点牌 → 选第二张 → 使用则进选目标、响应则直接打出。玩法选择器里多一条「两张手牌当【杀】使用（丈八蛇矛）」 |
| 测试 | 两红/两黑/一红一黑对仁王盾（**三条都单测**）、无色杀仍被藤甲免疫、必须两张、不许同 id、计入出杀次数、南蛮响应、提示里整手牌可点、日志与弃牌堆账目；随机对局冒烟里专门统计并断言这条分支真被走到 |

**踩到的坑（值得记）**：`isRed(card)` 只能回答「是不是红色」，而**无色既不是红也不是黑**。
原来判仁王盾用的是 `!attack.cardRed` —— 一旦引入无色杀，这个写法会把它当成黑色，
正好把规则弄反。所以顺手把「颜色」收口成一个返回三态的 `cardColor()`，
并在 `cardColor` 的注释里写明「别再用 `!isRed` 当黑色用」。

### 5.23 方天画戟的**两个版本**（军争版补齐）

方天画戟是**同名两张牌、两个模式两套效果**的典型（§5.14 早就记下了这个隐患）：

- **国战版**（势备篇，§5.19）：指定**任意名势力各不相同**的角色及未确定势力的角色；
  一人出【闪】则此【杀】对**其余目标全部无效**。
- **军争版**（身份局）：只有当这张【杀】是**你最后的手牌**时，才可以**额外**指定至多
  两个目标（共 3 名）；每个目标**各自独立结算**，谁闪谁不闪互不影响。

**改的过程中发现一个真 bug**：`playSha` 里那段「势力各不相同」的校验当初是**不分模式**写的，
所以军争局的方天画戟一直在按国战规则走（多目标还要求势力不同），而悬停提示却说它「尚未实现」。
现在两套规则收口在 `fangtianRule(state, source, card)` 一处，按 `state.mode` 分，
返回 `{ max, distinctFactions, abortOnDodge }`：

| 字段 | 国战版 | 军争版 |
|---|---|---|
| `max` | ∞（任意名） | 3（额外至多两个） |
| `distinctFactions` | true | false |
| `abortOnDodge` | true（一人闪则其余无效） | false（各目标独立） |

`AttackContext` 因此多一个 `fangtianAbortOnDodge`——`finishAttack` 只在它为 true 时清空
`fangtianQueue`，否则照常打下一个目标。界面侧对应的就是 `shaMaxTargetsFor`（同一个判断，
国战 99 / 军争 3，且军争要「这是最后一张手牌」）。

**顺手修的一处时序问题**：多目标【杀】以前按**玩家点选的顺序**结算，而官方是「目标同时确定、
效果从使用者的下家起按**座次**依次生效」。国战版「一人闪则其余无效」让顺序有实际影响
（先结算的人挨打、后面的全免），点选顺序就变成可利用的东西了。现在 `startAttack` 里统一
`sortTargetsBySeat` 排一遍。

**至此牌堆里没有任何一件装备是「没实现」的**：`EQUIP_NOT_IMPLEMENTED` 与
`EQUIP_NOT_IMPLEMENTED_GUOZHAN` 两张表都空了（表还留着，以后加牌时照旧标注）。

### 5.24 冒烟测试的「假确定性」修正

`tests/smoke.test.ts` 原本只给**决策**用了种子，牌序仍是 `createGame` 里的 `Math.random()`——
所以同一颗种子在不同运行顺序下会跑出不同的牌，`hits.zhangba > 0` 这种覆盖断言会**偶发失败**
（补完方天画戟那天就真的在整套跑里挂了一次，单独跑又是绿的）。

修法：`createGame` 的 opts 多一个 `rng`（缺省仍是 `Math.random`，生产行为不变），
冒烟测试用 `seededRng(seed * 7919)` 洗牌。现在连续跑几次结果完全一致。
**教训**：「固定种子」要连**牌序**一起固定，只固定决策是假的。

### 5.21 无懈可击的**抵消链**（无懈对无懈）

以前这里是**简化口径**：任何一张【无懈可击】都把整张锦囊取消掉，而且不能互相抵消。
这轮按官方规则重做成了**抵消链**：

> 无懈可击有两种用法：抵消一张锦囊对**一名角色**的效果，或者抵消**另一张无懈可击**。

**模型**：`TrickContext.wuxieChain = { scope, count }`。

- 第一张无懈决定「抵消谁」（`scope`），`count = 1`；
- 之后每再打出一张无懈都是在**抵消上一张** → 只把 `count++`（翻转，不再选目标）；
- 于是 **奇数张 = 已抵消，偶数张 = 效果恢复**（`negatedSeats(ctx)` 据此返回）。

这样普通无懈与无懈·国就成了**同一套机制**，只差 scope 的大小（一名角色 vs 一名角色 + 同势力
尚未结算者）。规则里那条「无懈·国被抵消时**全部**效果都被抵消」也自然成立——toggle 的是整片 scope。

**几个跟着改的点**：

1. **不再「整张取消」**。打完一张无懈**不回到出牌阶段**，而是重开一轮询问
   （从刚打牌的人的下家开始，**这一轮连锦囊使用者本人也问**——他可以用无懈保住自己的锦囊）。
   每张无懈都要弃一张牌，所以循环必然收敛。锦囊最终由 `resolveTrick` 结算，
   被抵消的角色由各结算函数自己跳过（这套「跳过」是上一轮为无懈·国铺好的）。
2. **单目标锦囊被抵消 = 整张没了效果**（`trickFullyNegatedForSingleTarget`），与以前一致。
3. **AOE 的一轮无懈只能抵消一个人**（多目标时会让玩家选抵消谁）。这是规则上的正确行为，
   原来的「整张取消」反而是错的。
4. `wuxieScopeCandidates` 现在按牌型给出**真正会受影响的人**：无中生有/挟天子只有使用者、
   桃园/五谷是全体、以逸待劳是同势力、火烧连营是同一队列、敕令是没有势力的人、
   联军盛宴是「你 + 那个势力」、勠力同心是大/小势力全体。以前这里退回「所有存活角色」，
   会出现「抵消【无中生有】对乙的效果」这种什么也不会发生的选项。
5. 顺手补了【挟天子以令诸侯】被抵消时直接作废（以前少这一处判断）。

### 5.22 无懈可击的**逐目标时机**（§5.21 那条「已知未做」已补上）

官方时机是「目标锦囊牌生效前」。群体锦囊是**每名角色生效前各一次**——所以「先看乙怎么应对，
等轮到丙时再抵消丙」这种打法是成立的。现在按这个做了：

- 新增 `openWuxieWindow(state, ctx, onDone)`：开一次询问窗口，`onDone` 是这轮问完接着做什么。
  `Pending.wuxieQueue` 多一个 `onDone`（不给＝结算锦囊，逐目标的窗口给「继续结算这个目标」）。
- 窗口出现在两处：**锦囊开始结算前**一次，以及**每名角色生效前**各一次。
  加了逐目标窗口的是：**南蛮入侵 / 万箭齐发**（`enterTrickResponse`）、
  **五谷丰登**（`wuguStep`）、**以逸待劳**（`yiyiStep`）、**敕令**（`chilingStep`）、
  **火烧连营**（`huoShaoStep`）。
- 窗口关掉之后要**重新判一次**是否已被抵消（`respondForCurrent` / `*ResolveCurrent`）：
  窗口里可能刚有人把这个角色抵消掉（那就跳过他去下一个），也可能有人抵消了那张无懈（照常结算）。
- 被抵消过的角色**不再被问**、也不吃效果，日志写明「已被【无懈可击】抵消，不再响应」。

**顺手做的两点**：

1. **身上没有无懈的人根本不会被问**（`canUseWuxie`）。这是**纯 UX 优化、不改规则结果**：
   没有无懈的人在那个时机只能弃权。而且**不泄露信息**——每个人只在自己持有无懈时才收到询问，
   别人有没有被问看不到，日志也不记弃权。不做这一步的话，群体锦囊逐目标询问会变成刷屏式点击。
2. **无懈的提示里带上「现在轮到谁」**（`是否使用【无懈可击】抵消【南蛮入侵】对 乙 的效果？`），
   否则逐目标窗口下玩家不知道自己在拦谁。

**为什么只给这五个加逐目标窗口**：时机只有在**两个目标之间状态会变**的时候才观察得到区别
（前一个人响应/弃牌/明置/进出濒死，后者才可能改变你对「要不要拦下一个」的判断）。
其余群体锦囊本引擎是一次过算完的：桃园结义＝全体回血、勠力同心＝全体横置或摸牌、
联军盛宴＝全体摸一张并重置、调虎离山/铁索连环＝全体同时改状态——它们的目标之间没有可观察的
状态变化，所以「开始结算前那一轮 + 可以指定抵消谁」已经等价。**真要逐目标也做得到，
只是没有可观察的差别、不值得多背一层续接。**

**还没做**：延时锦囊在判定阶段生效前的那次无懈机会（例如判定牌生效前无懈【乐不思蜀】）——
判定流程还是同步的，与「闪电的雷电伤害不触发护心镜」是同一类限制。

  水淹七军（弃置装备区所有牌）、贯石斧（一次弃两张，走 `discardOwnCards`）、
  悲歌梅花（伤害来源弃两张，新原语 `api.discardCards` 一次交出去）。
- 单张失去也会带一个全新的 eventId，所以「两次分开的失去」照样各触发一次（有对照组测试）。
- 测试：甘露让凌统一次失去两张 → 只问一遍；水淹七军弃光 → 只问一遍（且后面的牌会等这次
  询问结束再弃——挂起机制的连带效应，测试里按真实顺序驱动）；两次分开拆牌 → 各问一遍。

### 5.32 清「已实现武将里的简化」之四：伪帝的账本改成「归因到人」

袁术·伪帝要「本回合**从牌堆**获得过牌的其他角色」。原来记的是**牌 id 列表**（drawOne 里盖戳），
于是「A 摸到的牌被 B 顺手牵羊拿走」之后，B 按牌 id 查也会被算成「从牌堆获得过牌」。

改成按**意图结束时的首次持有**归因：`state.deckGainOwner`（牌 id → 座次）在每次意图结束时更新——
一张牌第一次出现在某人手里、它在本次抽牌账本里、且还没归过别人 → 才算他摸的。偷来的不会被算，
摸牌人转手之后也不再算（牌不在他手上了）。
已知偏差：同一手意图里「摸到又立刻弃掉」的牌不会归因（它没在意图结束时留在手上）。

测试：正例（自己摸的牌还在手上 → 点得到）＋被抢走的两面（抢的人不算、原摸牌人也不再算）——
后者用「袁术打郭嘉 → 遗计摸两张 → 两张都被顺手牵羊拿走」这条路构造，全程都在袁术的回合内
（账本是按回合清的，跨回合就没了）。

### 5.33 清「已实现武将里的简化」之五：忘隙的「若该角色存活」

李典·忘隙：造成／受到 1 点伤害后，「**若该角色存活**」才能各摸一张。本引擎伤害层的顺序是
「伤害后钩子 → 濒死」（官方是「濒死结算 → 伤害后钩子」），所以以前只能用 `hp>0` 代指，
代价是「被打进濒死又被救回来」的人不触发（官方要触发）。

改法（只动这一个技能，不翻伤害层顺序）：在伤害后时机发现对方 `hp ≤ 0` 时**记一笔待办**
（`flags.wangxiPending`，按座次排队），等 `nearDeathResolved`（本会话刚补上的时机）拿到
「活没活下来」的结论再问——救回来照样触发、没救回来不触发，与官方一致。

测试：把对方打进濒死 → 用桃救回 → 忘隙的询问在濒死结算**之后**弹出、双方各摸一张；
对照组：没人救、真的阵亡 → 不触发。

### 5.34 `useCard` 转成可挂起时机 —— 铁骑的判定也能被鬼才改判了

「时机可挂起」这件事一直在按需推进（原因是钩子里发问会被后续流程静默覆盖）。这次轮到
`useCard`（**九个**派发点：实体杀 / 技能驱动的实体杀 / 桃 / 酒 / 装备 / 延时锦囊两条 /
即时锦囊 / 虚拟锦囊）。

- 改法就是那套固定手法：`runHooks` → `runHooksPausable`，并把**后续步骤挪进回调**——
  杀是 `becomeTargetFor`、锦囊是 `startTrickResolution`、桃/酒/装备/延时锦囊是空回调
  （它们本来就在钩子之后就结束了）。
- 顺手补了一处漏登记：可挂起路径（`runHooksFrom`）原本没有调 `markCardUsed`，而它和同步路径
  （`runHooks`）是两套。转换之后「本回合出牌阶段用过的牌」账本（吕蒙·克己 / 谋断）与
  「指定过其他势力」（卞夫人·约俭）都会走这条路，漏了就会被静默清空——四个既有测试立刻抓住了它
  （这正是「转换时机时先跑全套测试」的价值）。注意只在**链条第一次**进入时登记（`from === 0`），
  续接时会再进这个函数。
- **马超·铁骑**随之接回统一的 `api.judge`：判定经过「判定牌生效前」，鬼才/鬼道可以改判、
  天妒可以收牌。至此 roster 里**没有改不了判定的技能**了。
  （验证方式：把 `src` 暂存起来跑那条新测试，旧引擎下确实失败——这次没有靠推测下结论。）
- 一个诚实的更正：我原以为孙策·激昂的询问也会被吞，实测**转换前后都通过**（引擎在成为目标那条
  路上本来就有「发现已有 pending 就续接」的保护）。两条激昂（使用侧 / 成为目标侧）仍然写进测试，
  当作这次改造最该盯的回归面。
- 仍未转换：`nearDeath` / `beforeResolve` / `afterResolve` / `discardPhase` / `death`
  （`afterUse` 目前只在【调虎离山】那条路派发）。

### 5.35 逐个武将的实战冒烟（26 名 × 主/副将位 = 52 局）

单元测试是「按剧本走」，撞不出「某个技能在多层询问之后忘了把控制权还回去」这类问题——
它的症状是 pending 变成 null、**整局静默卡死**。`smoke.test.ts` 原来只有 12 局随机对局
（全随机武将，抽到谁算谁），新武将不保证被覆盖到。

补了一层**逐个武将**的冒烟：把名单里的武将固定到 0 号位，随机驱动到分出胜负（步数上限 4000），
主将位与副将位各跑一遍。名单挑的是机制最复杂/最近实现的那批 26 名（眩惑、千幻、将略、寄篱、
调归、伪帝、举荐、雉盗、集智、克己、旋略、枭姬、铁骑、天义…）。

场景比原来贴近实战：其余座位用**随机国战武将**（不是白板，这样拼点、借技能、势力技这些
跨武将互动才有机会发生），并且**其中两个与 0 号位同势力**（否则「与你势力相同的角色」这类
技能永远没有对象，测了等于没测）。

跑起来很快（53 个用例约 1.5 秒），所以顺手当成了这类改动的回归网。

**它抓什么、不抓什么（实测过）**：这层冒烟的不变式是「任何时刻都必须有一个可行动的 pending」，
也就是**控制流**问题（询问覆盖、续接丢失、忘了 returnTo → pending 变 null 静默卡死）。
它**不保证技能逻辑被覆盖**：拿 11 名新武将实测，22 个技能键里只有 5 个（恩怨/眩惑/将略/雉盗/千幻）
在这 52 局里真被触发过——随机驱动很难凑齐「手里正好有装备牌」「正好有人本回合摸过牌」这种前提。
技能行为仍然以单元测试为准；这层网负责的是「别卡死、别抛错」。

### 5.36 观星「任意顺序」（最后一条技能侧功能缺口）

诸葛亮·观星官方是「观看牌堆顶 X 张，将其中任意数量的牌**以任意顺序**置于牌堆顶，其余
**以任意顺序**置于牌堆底」。原来只能选「哪些沉底」，留在牌堆顶的必须保持原序。

改成官方形状的两步（都在同一个 `pickCards` 里，顺序＝点击顺序）：

1. 先选**置于牌堆顶**的牌（按点击顺序＝从最上面往下数）；**一张不选＝都不动**（保留旧行为，
   也不再多问一步）。
2. 再从剩下的里选**置于牌堆底**的牌（按点击顺序＝沉底后先抽到的先点）；一张不选＝其余按原序沉底。

未点进「沉底」的其余牌接在顶堆下面、保持原序——这样「只想把某几张放到顶上前」这类操作一步就够。
界面配合加了个小改动：选牌浮层给选中的牌标**序号**（点击顺序），否则「按点击顺序」玩家看不见。

⚠️ 写的时候撞出一个真 bug：第二步一张不选时，`middle`（接在顶堆下面那批）与 `bottom`（沉底那批）
都等于 `rest` → **同一张牌被放进两个数组**，牌堆里出现两张同样的牌。新加的顺序测试立刻抓住了它。

### 5.37 摘掉曹操/刘备身上的 `isLord`（君主规则的伏笔变成了错误行为）

`isLord` 会打开四条君主行为：① 与**任何**同势力武将都算珠联璧合（白拿【珠联璧合】标记）；
② 亮将必须主副将**一起**亮；③ 只能当主将（不能作副将）；④ 不会成为野心家。
当初把它挂在曹操、刘备身上是「给将来补君主留伏笔」，但官方国战里这两位就是普通武将，
君主是**另外两张牌**（君曹操 / 君刘备）——于是这四条一直在错误地生效。

改法：摘掉这两个标记，并把这层意思写进注释（将来做君主时新增独立武将条目，那几个分支自然生效）。
顺带加测试：曹操/刘备能当副将、且不会白拿珠联璧合。

### 5.38 模糊测试：抓到两个真 bug，并留下一份待修清单

写了一套随机对局的不变式（`packages/engine/tests/fuzz.test.ts`）：用**轮换的高风险武将**阵容
（观星/五谷/甘露/奇策/木牛流马/鬼才…）跑 60 局随机对局，每步检查「同一张牌不能同时存在于两个
区域 / 牌总数不变 / 不问阵亡者」。这类 bug 单元测试很难撞见——它需要一条具体的随机路径。

**它抓到的两个真 bug（已修 + 已加确定性单元测试）**：

1. **荀攸·奇策**：原来是「先打出那张虚拟锦囊、再问是否变更副将」。如果那张锦囊是
   【挟天子以令诸侯】那类**会结束出牌阶段**的牌，回合已经推进到下家，这个询问就落在了一个
   **已经结束的流程**上——答完之后 `pending` 变 `null`，整局静默卡死。改成**先问、再打**
   （变更副将与那张锦囊的结算互不影响，所以提前问不改变结果）。
2. **司马懿·鬼才 / 张角·鬼道**：替判时技能自己把打出的牌 `toDiscard` 了一次，而这张牌会
   **成为新的判定牌**、判定结束时还要由 `disposeJudgeCard` 再处置一次 → **同一张牌在弃牌堆里
   出现两次**。改成只从手里摘掉、交给判定流程统一处置。

**留下的待修清单**（都在 fuzz 文件末尾的 skip 用例里，含复现种子与步骤）：

- **重复牌**（**在稳定时刻**也会撞到，所以不是「在飞」的假象）：`seed=2 第 457 步` g105、
  `seed=26 第 448 步` g105、`seed=35 第 346 步` g101——**除了已修的两个之外确实还有别的来源**；
- **`pending` 变 null**（控制权丢）：最常见的一类。**已修一条**：吕范·调度把装备移给队友时
  会嵌套触发别人的询问（枭姬那类），那次询问结束之后没人还控制权 → `pending` 停在 null、
  整局卡死。修法是新原语 `api.returnPlayPhase(seat)`——技能链条收尾时显式还控制权
  （有询问挂起时不生效，不会抢流程），并配了会失败的对照测试。
  ⚠️ **同一类还有别的出口**：`seed=47 第 7 步`（刘备·仁德给牌之后）、`seed=29 第 34 步`
  （还是调度 + 枭姬，说明调度链里还有分支没兜住）、`seed=8/14/25/31/32/40` 等。
  下一步建议：与其逐个技能补 `returnPlayPhase`，不如在引擎里加一道**统一的兜底**——
  `drainResume` 排空之后若 `pending === null` 且不是回合切换中，就把出牌阶段还给回合玩家；
  但这需要先确认哪些「pending 为 null」是合法的中间态，别把真流程盖掉。
- ⚠️ 排查时的第二个坑：**模糊测试的驱动必须是同一份代码**（现已抽成 `tests/fuzzHarness.ts`）——
  我先前另写「定位器」时两边的驱动有细微差异，同样的种子跑出不同的对局，白查了一轮。
- **丢牌**：`seed=4 第 89 步`（一次「choice 选不发动」之后 g47 消失）、`seed=20 第 16 步`、
  `seed=14 第 72 步`（鬼才替判之后两张消失）；
- `seed=1/18/22`：「在问一个已经阵亡的角色」——需要先判断是否合法（询问挂起期间当事人死了）。

⚠️ 排查时的坑：我另写了一个「定位器」逐局复现同一套种子，却一局都没抓到 —— 两者只有驱动细节的
差异，但我**没能把差异钉死**（这一轮到此为止）。下次接着查这条线索：先让定位器与 fuzz 用例
**逐字节对齐**（同种子、同驱动、同一处检查），再顺着 g105 的两处 `where` 去定位来源。

这三条不变式目前都没干净，所以用例先 `skip`（不让 CI 变红），但复现方式与已定位现场都写在文件里。

### 5.39 「控制权丢失」加统一兜底（把整局卡死降级成控制权还给该动的人）

上一节那条 `pending → null` 的追踪有了个阶段结论。逐个技能补 `returnPlayPhase` 治不了本
（我追的一个现场里，外层链条**根本没走到收尾**——探针一个都没触发，说明嵌套询问把外层的续接
整个吞掉了），所以在 `applyIntent` 里加了一道统一兜底：

> 续接队列排空之后，若 `pending === null`、游戏未结束、**回合座次没变**（变了说明这个意图
> 正常结束了回合，不能乱塞 pending）、且阶段是**出牌阶段**，就把出牌阶段还给回合玩家。

- 价值可量化：它把我逐个追的 **13 个种子**（`8/14/23/25/29/31/32/40/47/21/37/38/45`）
  一次修好，「整局静默卡死」降级为「控制权还给该动的人」。
- **这一类现在修干净了**：把检查跑满 60 局全过；撤掉兜底它就会红（`seed=13/21/25/29/37` 等），
  所以那条 fuzz 用例（`tests/fuzz.test.ts` 的「任何一步都要有 pending」）已经**打开**当回归网。
  ⚠️ 更正一条我自己写错的结论：先前提到的「扩大到 60 局后又冒出 seed=1 第 202 步、2/905、6/28…」
  是**那条检查自身**的假警报（漏了「游戏正常结束那一步本来就 pending=null」），不是引擎的问题。

### 5.40 查「重复牌」时解开的一个谜：种子对这套引擎**不完全有效**

追重复牌（线索：重复的总是同一张【闪电】）时，一直卡在一件事上：**同一个种子、同一个驱动，
「用例」和「定位器」跑出来的对局却不一样**——同一个 bug 一会有一会没，白查了两轮。

原因找到了：引擎里仍有 **10 处 `Math.random()`**（随机选牌、军令的「随机抽两张」、左慈的魂牌、
悲歌的弃牌…），而 fuzz 只给「洗牌 + 发将 + 摸牌」注入了种子（`createGame` 的 `opts.rng`）——
**所以固定种子只固定了一部分对局，这些路径每次跑都不同**。

- 这条对**所有**按种子复现的排查都成立：以后别指望「seed=2 第 655 步」能稳定重放。
- 想让这层网真正可回归（也让这类 bug 能稳定复现），下一步很明确：**把那 10 处 `Math.random()`
  改成走 state 上的随机源**（把 `opts.rng` 存进 `GameState` 即可，10 个点、改动小、可测）。
- 顺便验证一下：改完之后，fuzz 的那两条 skip 检查（重复牌 / 牌张守恒）应该能稳定复现，
  那时再逐个定位才有效率。

### 5.41 让种子真正可复现（随机源收口）+ 重复牌线索收窄到延时锦囊

- **随机源收口**：引擎里最后 10 处 `Math.random()`（随机选一张手牌、军令的「随机抽两张」、
  左慈的魂牌、悲歌的弃牌…）改成走 **`state.rng()`**（`createGame` 的 `opts.rng` 会存进 state）。
  从此**固定种子能稳定重放**——之前同一个种子每次跑出来的局面都不同，害我白查了两轮
  （「用例和定位器对不上」「同一个 bug 一会有一会没」都是这个原因）。
- **重复牌线索收窄**：确定性修好之后，把 fuzz 的种子数临时调到 300，**稳定复现 6 次**
  （`seed=64 第 235 步`、`143/226`、`172/107`、`189/107`、`194/428`、`266/51`），
  重复的牌是 **g95 / g96 / g103 / g104**——查证它们**全是延时锦囊那一批**（g103 是【闪电】）。
  所以来源就在「判定区的牌」这条路径上；已排除两处（判定阶段开头先清空判定区 ✓、
  `moveFieldCard` 搬判定牌是先 splice 再 push ✓）。下一步：按上面的种子重放，在用例内部用
  `cardLocations` 打出重复牌的两个 `where`，顺位置定位。

### 5.42 重复牌结案（大部分）：`api.transferCard` 没处理判定区

上一节把线索收窄到「判定区的牌」之后，**确定性种子**让定位一次到位。跑 300 局、把每处的
两个 `where` 打出来，6 次重复里有 4 次是同一个形状：

```
where = s2.hand[1] | s3.judg[0]        ← 同一张【闪电】既在新主人手里，又在原主人判定区
这一步 = P2 选择了「获得其【黑桃A·闪电】」（马谡·制蛮：防止伤害，获得其装备/判定区一张牌）
```

根因：`api.transferCard`（「把某人的一张牌转给另一个人」的公共出口）只处理了**装备区**和
**手牌**，没有判定区分支 —— 制蛮（以及将来任何走这条路的技能）从判定区拿牌时，
牌被推进新主人手里、却**没有从原判定区摘掉**。已补上判定区分支，并配了会失败的对照测试
（`engine.test.ts` 的「制蛮：拿走判定区的牌要摘干净」）。**跑 300 局从 6 次降到 4 次**。

**剩下那 2 处也一起结了**（同一轮里顺着日志 `重铸了【知己知彼】，摸了一张牌` 找到的）：
`doRecast` 只从**手牌**删牌（`removeCard(player.hand, …)`），删不掉也不检查，然后**无条件**把牌
推进弃牌堆——如果这张牌其实是邓艾的「田」（或木牛流马的扣置牌），就成了「同时留在田里 + 进了
弃牌堆」（`seed=172 第 107 步` g95、`seed=189 第 107 步` g96 就是这两处）。改成走
`takeUsableCard`（手牌 → 田 → 扣置区都能摘）并在摘不到时直接返回。

✅ **重复牌这一类至此清零**：跑 300 局 0 次（修前 6 次）。这条检查已**打开**成正式断言
（`tests/fuzz.test.ts` 的「200 局随机对局里都不出现重复牌」），并验证过有牙——把两处修复
一起撤掉，它立刻报 `seed=172/189` 那两处。⚠️ 顺带记一个待核的规则问题：官方「田」只能当
【顺手牵羊】用（急袭），而本引擎允许把它当**可重铸牌**重铸——机制上已经干净（不再一牌两地），
但这条是否该禁止，等确认官方 FAQ 再定。

### 5.43 「丢牌」结案：牌张守恒 ≠ 数牌，续接队列的**排序**错了

上一节末尾记的「丢牌」类（`seed=4 第 89 步` 等）这一轮查清了，结论分三层：

**一、先纠正度量：不能直接数牌。** 一开始的检查是「牌堆+弃牌堆+手牌+装备+判定区+田+千幻
的牌数应当恒等于初始值」，结果几十个种子都报「少 1-2 张」——但逐张追下去，**每一张都是
结算中途正常在飞**：判定牌被判定流程拿在手里、五谷丰登/观星亮出来的那一池、拼点亮出的两张、
木牛流马扣置的（cargo，代码里只在装备区数过，挂到手里时就被当成丢了 ✗）。判据改成
「**在稳定时刻（出牌/弃牌阶段的挂起）连续缺席多少个稳定步**」才对准了真正的问题——
积压（`tests/fuzzHarness.ts` 的 `makeCardWatch`，标定见函数注释）。

**二、真 bug：续接队列（`resumeQueue`）的入队位置搞错了。** 队列里放的是「被询问打断的后续」，
但**从续接内部再入队**的条目以前也排到**队尾** —— 它比队里所有等待者都更内层，
排到后面就意味着外层（例如伤害结算）先跑完、把 pending 挂回去，队列再也等不到「pending 为空」
的时机，内层续接被**永久搁置**。实测「恪守判定拿回判定牌 + 判红摸牌」被推迟了三个回合
（`seed=165`：判定第 7 步，结算第 20 步），屯田/悲歌的判定牌被搁置 27-44 步。
修法：`pushResume` 分两种入队位置——主流程排队尾、**续接/询问回调内部插队首**
（`resumeDepth` 计数，见 `engine.ts` 的 `pushResume` 注释）。搁置 ≥6 步的从 414 次降到 8 次，
且这 8 次全是五谷丰登/观星的亮出池（合法在飞）。这条不变式已开成断言
（`fuzz.test.ts` 的「200 局……不出现重复牌 / 长期缺席」）。

**三、又两处真 bug（都是这一轮的守望器报出来的）：**
1. **屯田 + 天妒**：`api.judge` 的 `keepCard` 分支只告诉调用方「你不能拿这张牌了」，
   牌本身**谁也不管** —— 判完就从全场消失；红桃那半句还会先把它推进弃牌堆，于是又「两头都在」。
   修法：`gainer` 存在时由 `api.judge` 交给天妒，调用方把 `canTake` 判断提到红桃判断**之前**。
   配了对照测试（`engine.test.ts` 的「屯田 + 天妒……」）。
2. **随机源还有漏网的**：军令抽两张（`shuffle([...ARMY_ORDERS])`）、牌堆洗完重洗
   （`shuffle(state.discard)`）没传 `state.rng`，退回 `Math.random` —— 同一个种子跑出不同对局。
   已全部接到 `state.rng`，并加了一条**同种子重放**的断言（`fuzz.test.ts`），
   它在修之前就报「同一个种子两遍结果不同」。

**四、（续）跨回合的陈旧续接：数据丢失那半已拦住，触发时机仍是错的。**
`runHooksFrom` 在钩子返回后只要看到**任何** pending 就当作「是我这个钩子问了话」而挂起
「剩下的钩子」；若那个 pending 其实来自别的流程，这条链会一直等到下一次队列排空才醒。
`seed=7` 里它醒过来时棋局已经过了 **8 步**，重新触发了【鬼才】，替一个早已结算完的判定
打出替换牌。追到最里面，**伤害是这样造成的**：询问只有一个槽（`state.pending`），
而「钩子先问玩家、再按回答决定」是跨步的 —— 那条链在判定正问着【鬼才】时又问了【屯田】，
把鬼才那条问**覆盖**掉了：鬼才的回答永远等不到，而屯田的答案被当成鬼才的回答喂给判定，
钩子打出的那张替换牌就写进了一条**已经结束**的判定链的盒子里，然后凭空消失
（`seed=7 g41` / `seed=132 g79` / `seed=175 s37`，都是【闪电】判定 + 鬼才替换一路）。

**已经兜住的**：`JudgeBox` 现在带着「这条判定链还活着吗」的标记（`chain.dead`）——
链跑完时置位，之后再往盒子里写替换牌就把那张牌**置入弃牌堆**（按「打出的牌」处理），
不再凭空消失。三个种子由此清零，fuzz 的缺席检查里**不再有跳过的种子**；
并且验证过有牙：把这段兜底撤掉，它立刻报回这三个种子。

**没修完的**：触发时机仍然是错的（那条链本来就不该在棋局翻篇之后才醒、不该重复触发技能）。
按「已有 pending 就不许覆盖」来根治**试过、行不通**：技能在阶段里发问，靠的就是覆盖
出牌/弃牌阶段的空位来接管控制权 —— 一刀切成「不许覆盖」会挂 **93** 项测试，
连「只禁止覆盖 question 类 pending」也是同样的规模（两个变体都试过并已回退）。
真正的修法是给续接条目带上「归属哪条链」的标记，唤醒时校验现场还是不是那一手。
在那之前：**牌不会丢**，但一次判定的询问可能来得偏晚、并可能被重复触发一次。

**五、测试**：`pnpm -C packages/engine test` 774 项全绿（新增 屯田+天妒 对照 1 项、
确定性 1 项）；引擎测试里两处「军令抽两张」的桩也顺手修了（只 mock 了全局 `Math.random`，
军令改走 `state.rng` 之后就成了看运气的偶发失败）。
