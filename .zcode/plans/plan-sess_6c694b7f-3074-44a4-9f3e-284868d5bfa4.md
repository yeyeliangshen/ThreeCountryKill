# 国战扩充：魏蜀吴群 96 将 + 势备篇 + 国战规则

## 范围

| 做 | 不做 |
|---|---|
| 标准版 60 将（魏蜀吴群各 15） | **君主将**（君刘备/君张角/君孙权/君曹操）及君威、专属装备、大旗标记、替换同名武将、有君无野·君死全野、阵亡减同势力体力 |
| 君临天下 阵/势/变/权 32 将 | **野心家武将**（钟会/司马昭/孙綝/公孙渊）及拉拢人心 |
| 不臣篇单势力将 ≈6（董昭、徐庶、吴景、严白虎等） | **双势力武将** 12 名（孟达、许攸等，仅副将位那套规则） |
| 势备篇 52 张牌 + 合纵连横 + 大势力/小势力 + 横置 + 宝物区 | 已存在的「野心家」中局转化规则**保留不动**（人数超半时转换） |
| 国战专属牌堆（知己知彼、以逸待劳、远交近攻等） | |

**量化**：现有 24 将可用（其中 8 个只有部分技能）→ 目标约 **96 将**，即新增约 **72 名**、总计约 **210 个技能**。单文件现状：`heroes.ts` 1346 行、`engine.ts` 2255 行、测试 3403 行——三者都必须拆。

**已定的一处取舍**：曹操的 `isLord` 保留（作为以后补君主的伏笔）。副作用是它那四条君主特性在君曹操实现前一直生效，**曹操当前不能作副将**。会在代码与文档里标注。

**诚实估算**：按现有保真度（技能手写 + 测试），这是 **3～5 个月**的专注投入，不是几轮对话。主因是 210 个技能与约 18 项原语，不在牌上。计划按阶段切片，随时可停在某个阶段并保持一个能玩的完整状态。

## 阶段 0 · 冻结名录与原语需求矩阵（硬前置）

产出 `docs/guozhan-roster.md` + `packages/engine/src/data/roster.ts`：

- 96 名武将的 `id / 名 / 势力 / 性别 / 体力 / 包 / 技能名 / 官方原文链接`
- 52 张势备篇牌的同款表
- **核心产物：原语需求矩阵**——每个技能标注依赖哪个原语。阶段 2 的清单由这张表倒推，不凭感觉列，避免"原语做完发现还差一个、100 个技能返工"。

必须在此澄清的三处（调研结果有冲突）：

1. 标准版是否真为每势力 15 名（初版每势力 8 名，15 名应是并入后续包的口径）。
2. 不臣篇下篇的单势力将名单（只确认了上篇的董昭/徐庶/吴景/严白虎）。
3. 董昭的**军令**机制与徐庶的国战技能的确切规则——这两项决定阶段 2 要多开哪些原语。

同时定稿**不收录清单**：同名多版本（OL/手杀/新服/海外）只取一个（沿用 2019 典藏版 + 2025 调整口径），SP/线下限定将不收录。**注意 诸葛亮 与 卧龙诸葛亮 是两名不同武将**，各有独立 id。

## 阶段 1 · 工程底座（不涨武将数，但决定能否规模化）

1. `heroes.ts` → `heroes/` 目录，按势力分文件（`shu.ts` `wei.ts` `wu.ts` `qun.ts`）+ `heroes/index.ts` 注册。`HEROES`/`getHero`/`getHeroForMode` 等对外 API 保持不变。
2. `engine.ts` → `engine/` 目录（回合流程 / 伤害 / 锦囊 / 技能分发 / 建局），导出面不变。
3. 测试拆分：`tests/engine.test.ts` → 按包分文件，公共 helper 抽到 `tests/helpers.ts`。现有 178 个测试逐个搬家，不重写。
4. `Hero.pack` 字段（`standard|zhen|shi|bian|quan|buchen`）：支持按包筛选、按包玩、进度统计。
5. `Hero.modes` 字段：国战专属武将不再漏进军争/混战池（上轮加的 8 将已暴露这个缺口）。
6. 缺图时的统一占位牌面（现有实现退回纯文字，96 将下需要看得过去）。
7. hook / activeSkill 两套实现样板 + 检查清单，压低每将成本。

## 阶段 3 · 国战制度（去掉君主/双势力/野心家武将后，只剩四项）

1. **国战专属牌堆**——现在跑的是军争牌堆。国战有独立牌堆，含**知己知彼、以逸待劳、远交近攻**等军争没有的牌。这是"完整国战"的隐藏前提，也是牌层工作的地基。
2. **大势力 / 小势力判定**（某势力存活 ≥2 且为全场最多即大势力），以及依赖它的牌。
3. **横置 / 重置**状态与铁索结算。
4. **不计入距离与座次**（调虎离山）。

## 阶段 4 · 势备篇

1. 52 张牌的牌面数据（28 基本 / 17 锦囊 / 7 装备）。
2. **12 张新锦囊**：火烧连营、水淹七军、敕令、联军盛宴、勠力同心、挟天子以令诸侯、调虎离山、无懈可击·国。
3. **7 张新装备**，其中 **玉玺 / 木牛流马 是"宝物"——第 5 个装备槽**，`Equipment` 类型、快照、装备 UI 都要扩。
4. **合纵 / 连横**：出牌阶段限一次，把手牌中带「合」标记的至多三张交给与你势力不同的角色并摸等量牌；交给未确定势力角色则不摸牌。需要给牌增加"带合标记"的维度。
5. 明光铠 / 护心镜 / 玉玺 / 惊帆 的装备特效（`equip.ts`）。

## 风险与交付顺序

**三个主要风险**

1. **2.1 的控制流重构**——会碰所有伤害与结算路径，是唯一可能引入"整局卡死"类 bug 的地方。小步提交 + 密集回归。
2. **原语清单不完整**——所以阶段 0 的"原语需求矩阵"是硬前置；5.2 后的回顾是第二道保险。
3. **原画缺口约 80 张**——不阻塞开发（走占位），但界面观感会明显下降，属素材工作，需你并行准备。

**交付顺序**：0 → 1 → 2（2.1/2.2 单独 commit）→ 3 → 4 → 5.1 → 5.2 →（回顾）→ 5.3…5.10 → 6。

每一阶段结束时都有可运行、可回滚的状态。阶段 1～3 期间武将数不涨，这是"先集中补引擎能力"的必然代价；阶段 5 起每批都能看到一批新将进池。
