# Phase 2 — 国战 (Guozhan) 模式实现计划

## 范围与取舍

**本轮做**：
- 双将系统（主将 + 副将，`heroId` 保留为主将，新增 `deputyHeroId` 为副将）
- 阵营 = 国别（魏/蜀/吴/群，同阵营 = 同队）
- 暗将/亮将机制（开局双将暗置，出牌阶段可主动亮将，亮将后技能激活）
- 体力 = ceil((主将.maxHp + 副将.maxHp) / 2)
- 四阵营胜负（最后存活的阵营获胜，阵亡亮将）
- 新增 4 名吴国武将（当前池中吴国为 0，国战无法运作）
- 测试 + 浏览器验证

**本轮不做（留后续）**：
- 野心家（阵营过半机制）— 复杂且原计划只提"4 阵营胜负"
- 珠联璧合（特定武将组合奖励）— 留 Phase 3
- 阵营技/势力技（原主公技的扩展）— 留 Phase 3
- 鏖战（残局桃变杀）— 留 Phase 3
- 被动亮将（被杀/濒死时才亮将用技能）— 本轮只做出牌阶段主动亮将

## 设计要点

**双将字段策略**：保留 `heroId` 作为主将（现有所有代码不破坏），新增 `deputyHeroId` 作为副将。非国战模式 `deputyHeroId = null`，所有现有逻辑不变。国战模式两将都有值。这比 `heroIds[]` 数组方案破坏性小得多，且语义清晰（主将/副将分工明确）。

**技能激活**：新增 `activeHeroes(state, player)` 辅助函数，返回当前已亮将的武将数组。非国战模式返回 `[主将]`（行为不变）；国战模式返回已亮将的武将。`canUseAs`/`shaLimit`/`hooks` 均改为基于 `activeHeroes` 的并集计算——非国战行为完全不变，国战暗将时无技能、亮将后激活。

## 4. 引擎核心 — `packages/engine/src/engine.ts`

### `createGame`
- 国战模式：`k = 7`（覆盖默认 3），武将池排除 `neutral`
- 初始化 `deputyHeroId: null, heroRevealed: !isGuozhan, deputyRevealed: !isGuozhan, faction: null`
- 国战不分配 role/team（阵营由武将决定，在选将时设定）

### `onPickHero`
- 国战模式：验证 `deputyHeroId` 存在、在发到的将中、与主将不同、**同阵营**
- 设置 `player.heroId = intent.heroId`、`player.deputyHeroId = intent.deputyHeroId`
- 设置 `player.faction = mainHero.faction`
- 非国战：维持现有逻辑（只设 `heroId`）
- 日志保持通用 `${player.name} 已选定武将。`（不泄露选了谁）

### `finishDraft`
- 国战模式：`maxHp = Math.ceil((main.maxHp + deputy.maxHp) / 2)`
- 非国战：维持现有逻辑
- 先手座次：国战用座次 0（无主公概念）

### 新增 `onRevealHero(state, seatId, intent)`
- 仅国战模式可用
- 仅在自己出牌阶段（`pending.kind === 'play' && pending.seatId === seatId`）
- `intent.heroId` 须匹配主将或副将 id
- 设置对应 `heroRevealed`/`deputyRevealed = true`
- 日志 `亮将：${武将名}`（公开）
- 不改变 pending 状态（亮将不结束出牌）

### `runHooks` 改造
- 改用 `activeHeroes(state, player)` 获取已激活武将列表
- 收集所有武将的 hooks，按 priority 降序执行
- 非国战：`activeHeroes` 返回 `[主将]`，行为不变

### 新增 `activeHeroes(state, player)` 辅助
```typescript
function activeHeroes(state: GameState, player: Player): Hero[] {
  const heroes: Hero[] = [];
  if (player.heroId) {
    const h = getHero(player.heroId);
    if (h && (state.mode !== 'guozhan' || player.heroRevealed)) heroes.push(h);
  }
  if (player.deputyHeroId) {
    const h = getHero(player.deputyHeroId);
    if (h && (state.mode !== 'guozhan' || player.deputyRevealed)) heroes.push(h);
  }
  return heroes;
}
```

### `playSha` / `onPlayCard` 改造
- `getHero(source.heroId)!` → `activeHeroes(state, source)` 取并集判定 `heroShaLimit` 和 `heroCanUseAs`
- `heroShaLimit` = `Math.max(1, ...activeHeroes.map(h => heroShaLimit(h)))`
- `heroCanUseAs` = `activeHeroes.some(h => heroCanUseAs(h, card, type))`

### `respondSha` / `respondDeathSave` 改造
- 同上，用 `activeHeroes` 替代 `getHero(player.heroId)!`

### `doDeath`
- 国战模式：阵亡时亮双将 (`heroRevealed = true, deputyRevealed = true`)
- 日志加阵营：`${name}（${FACTION_NAME[faction]}）阵亡。`

### `checkWin` 新增国战分支
```typescript
if (state.mode === 'guozhan') {
  const alive = alivePlayers(state);
  if (alive.length === 0) return false;
  if (alive.length === 1) return setWinner(state, alive[0]!.faction ?? alive[0]!.seatId);
  const factions = new Set(alive.map(p => p.faction));
  if (factions.size === 1 && !factions.has('ambitionist')) {
    return setWinner(state, [...factions][0]!);
  }
  return false;
}
```

### `setWinner` 新增国战分支
- `winner` 为阵营 id（`'shu'`/`'wei'`/`'wu'`/`'qun'`）
- 日志：`游戏结束，${FACTION_NAME[faction]}势力胜利。`

### `applyIntent` 新增路由
- `case 'revealHero': return onRevealHero(state, seatId, intent);`

## 12. 测试 — `packages/engine/tests/engine.test.ts`

新增国战测试块（参照 2v2/军争测试结构）：

1. **选将**：`createGame(setup, 'TEST', { mode: 'guozhan' })` → 每人发到 7 张 → 选 2 张同阵营 → 验证 `heroId`/`deputyHeroId`/`faction` 正确设置
2. **同阵营校验**：选不同阵营的 2 将 → 应返回 error
3. **体力计算**：主将 maxHp 4 + 副将 maxHp 3 → `maxHp = ceil(7/2) = 4`
4. **暗将隐藏**：`toSnapshot` 对他人 → `heroId: null, deputyHeroId: null, faction: null`（未亮将时）
5. **亮将**：出牌阶段发 `revealHero` → 他人快照可见武将名和阵营
6. **阵亡亮将**：杀死玩家 → 他人快照可见双将名和阵营
7. **阵营胜利**：杀死某阵营所有玩家 → 剩余阵营获胜，`winner = 'shu'`/`'wei'`/etc
